# Institute Connection (Institute QR) — INST-QR-01

Owner domain: `tenant-management`. Endpoint group contract + mobile integration handoff.

## 1. What it is (and is not)

The Institute QR is a **public, shareable** pointer to one institute. Scanning it only
**selects the institute**. It is not a credential, session, API key, device-enrollment
secret or operator code, and it grants no sign-in, course or payment access. The student
still signs in normally on the institute's own site (or, later, in the student app).

## 2. Connection URL (v1)

```
{INSTITUTE_CONNECTION_BASE_URL}/connect/v1/{connectionCode}
e.g. https://lms.example.lk/connect/v1/1698fa5e1ca4
```

- `INSTITUTE_CONNECTION_BASE_URL` (`app.institute-connection.base-url`): platform-owned
  origin, scheme + host (+ port) only. Must be `https` except in the local profile. A
  malformed value fails startup; an empty value makes the admin endpoints return `503
  INSTITUTE_CONNECTION_NOT_CONFIGURED` and the resolver `404`.
- `connectionCode`: `^[a-z0-9]{12}$` (12 lowercase hex chars, 48 random bits), column
  `tenant.connection_code` (V127). Generated by the database, `UNIQUE`, **immutable**
  (trigger), and **never reissued**: deleting a tenant row records its code in
  `retired_institute_connection_code`, and inserting a tenant with a retired code fails.
- The URL contains no name, subdomain or custom domain, so renaming the institute or
  changing its subdomain/custom domains never changes the QR.
- `v1` is the contract version. A breaking change gets `/connect/v2/`; v1 URLs keep working.

## 3. Endpoints

All responses use the standard `ApiResponse` envelope and send `Cache-Control: no-store`.
No endpoint accepts a `tenant_id`, redirect target or role from the client.

### `GET /api/v1/tenant-config/institute-connection` — Tenant Admin

- Auth: tenant JWT on the institute's host; `BRANDING_SETTINGS`/`VIEW` (Tenant Admin,
  Read-only Auditor). Teacher/staff/student → `403`; no token → `401`; a token for
  another tenant's host → `401/403`.
- Tenant: the one resolved from host + token. Extra query params are ignored.
- `200` → `InstituteConnection` (below). `503 INSTITUTE_CONNECTION_NOT_CONFIGURED`.

### `GET /api/v1/platform-admin/tenants/{tenantId}/institute-connection` — Platform Admin

- Auth: `PLATFORM_ADMIN` role. Unknown tenant → `404 NOT_FOUND`.
- The response echoes `tenantId`; the UI refuses to render a result whose `tenantId`
  differs from the page's selected tenant.

`InstituteConnection`:

```json
{
  "tenantId": "uuid",
  "instituteName": "ABC Academy",
  "logoUrl": "https://… | null",
  "connectionCode": "1698fa5e1ca4",
  "connectionUrl": "https://lms.example.lk/connect/v1/1698fa5e1ca4",
  "qrPngBase64": "iVBORw0…",
  "connectable": true,
  "mobileApps": { "androidUrl": null, "iosUrl": null }
}
```

- `qrPngBase64`: PNG of exactly `connectionUrl`, rendered server-side with ZXing
  (`com.lms.common.qr.QrCodes`): error correction M, 4-module white quiet zone, 12 px per
  module (~490 px), black on white. No external QR service is used.
- `instituteName`: General settings `institute_name`, else the tenant name.
- `logoUrl`: uploaded site logo (short-lived signed URL), else Branding `logo_url`, else null.
- `connectable`: false unless the tenant is `ACTIVE` or `TRIAL` (the resolver 404s otherwise).

### `GET /api/v1/public/institute-connections/{code}` — public resolver

- Anonymous, GET only, excluded from `TenantResolutionFilter`: the tenant comes **only**
  from `code`. The `Host` header, query parameters and any redirect-like input are ignored.
- `404 NOT_FOUND` (one identical body) for: malformed code, unknown code, retired code, or a
  tenant that is not `ACTIVE`/`TRIAL`. Never falls through to another tenant.
- `200` → allowlisted fields only (no tenant id, status, contacts or settings), no cookies:

```json
{
  "version": 1,
  "connectionCode": "1698fa5e1ca4",
  "connectionUrl": "https://lms.example.lk/connect/v1/1698fa5e1ca4",
  "instituteName": "ABC Academy",
  "logoUrl": "https://… | null",
  "siteOrigin": "https://learn.abc.lk",
  "signInUrl": "https://learn.abc.lk/login",
  "mobileApps": { "androidUrl": null, "iosUrl": null }
}
```

- `siteOrigin`/`signInUrl` come from `TenantLookupApi.tenantOrigin` with
  `app.public.tenant-url-template`: the tenant's **verified ACTIVE primary custom domain**
  (when custom domains are enabled for it) or `{subdomain}` filled into the template. Both
  are `null` when the template isn't configured.

## 4. Web fallback

`/connect/v1/{code}` (Next.js, `frontend/src/app/connect/`) uses neutral platform branding.
It shows the institute's name/logo and **Continue to sign in**, which links to `signInUrl`
(the institute's own existing login page, so institute context is carried by its origin and
the normal validated sign-in flow). Invalid/unavailable → "This institute link isn't valid",
no continue link. Query parameters are never used.

## 5. Mobile app handoff

Status: **no student mobile app exists in this repository.** Native support is not complete.
(The `NEXT_PUBLIC_AOC_MOBILE_APP_*` store URLs belong to the AOC secure video player,
ADR-025, not to a student app, and are deliberately not reused here.)

Integration contract for the future app:

1. Accept the QR text / link `https://{base}/connect/v1/{code}`. Reject anything else:
   different origin, version other than `v1`, or a code not matching `^[a-z0-9]{12}$`.
2. Call `GET https://{base}/api/v1/public/institute-connections/{code}`.
   - `200`: show `instituteName`/`logoUrl` and ask the user to confirm. Store
     `connectionCode` + `siteOrigin`.
   - `404`: "This institute link isn't valid". Do not keep or guess a tenant.
3. Sign in against the institute: `POST {siteOrigin}/api/v1/auth/login` (or the mobile
   login per ADR-031). Tenant identity comes from the host as on the web. The code is never
   sent as a credential.
4. Re-resolve the code periodically or on failure: `siteOrigin` may change (e.g. a new
   primary custom domain); the code will not.

Native association prerequisites (**missing; not invented**):

- Android App Links: package name, release signing-certificate SHA-256 fingerprint(s), and
  `/.well-known/assetlinks.json` served on `{base}`.
- iOS Universal Links: Apple Team ID, bundle ID, `applinks:{base-host}` entitlement, and
  `/.well-known/apple-app-site-association` served on `{base}`.
- Store listing URLs → `INSTITUTE_CONNECTION_ANDROID_APP_URL` / `INSTITUTE_CONNECTION_IOS_APP_URL`
  (https only). Until set, the UI says the app isn't available.

Until those exist, scanning opens the web fallback page in the phone's browser.

| `INSTITUTE_CONNECTION_BASE_URL` | `app.institute-connection.base-url` | empty (local: `http://lms.test:3000`; `docker-compose.prod.yml`: `https://${PLATFORM_DOMAIN}`) |
| — | `app.institute-connection.require-https` | `true` (local: `false`) |

| `INSTITUTE_CONNECTION_IOS_APP_URL` | `app.institute-connection.ios-app-url` | empty |
| `TENANT_URL_TEMPLATE` (existing) | `app.public.tenant-url-template` | empty |

`{base}` must be served by the Next.js frontend (which proxies `/api` to the backend), on a
platform-owned host. Locally `lms.test` needs a hosts-file entry. No DNS change was made.

## 7. Sharing (admin card)

All user-initiated; nothing is sent automatically and no contacts are read.

- **Copy connection link**, **Download QR (PNG)** (blob download, no server upload).
- **Share Institute QR** sheet: preview + editable message (the link is always kept).
  - Native share (`navigator.share`): PNG + message when `canShare({files})`, else message
    only. Cancelling shows "Sharing cancelled. Nothing was sent."
  - **Open in WhatsApp** (`https://wa.me/?text=…`) / **Open in email** (`mailto:?subject&body`):
    text only, no recipient. The sheet says the PNG must be downloaded and attached by hand.
  - **Download QR** and **Copy message** are always available. A clipboard failure (e.g.
    insecure origin) shows an error and selects the text; it never reports success.
- No existing messaging integration supports user-selected recipients with confirmation for
  this flow, so none is used. Bulk messaging is out of scope.
